# AWS 네트워크 기초 — 리전 · AZ · VPC · 서브넷

> EC2를 만들 때 **"서브넷을 선택하세요"** 에서 막히는 이유를 이해하기 위한 문서다.
> 우리 서버의 실제 값(`172.31.0.0/16`)을 예로 든다. 실제 구축 절차는 `Deploy/AwsSetup.md`.

## 큰 그림 — 다섯 겹의 상자

```
리전 (ap-northeast-2, 서울)
└── 가용 영역 AZ (2a · 2b · 2c · 2d — 서로 떨어진 데이터센터)
    └── VPC (172.31.0.0/16 — 내 전용 사설 네트워크)
        └── 서브넷 (172.31.16.0/20 — VPC를 쪼갠 한 덩어리, AZ 하나에 속한다)
            └── EC2 인스턴스 (사설 IP 172.31.22.197을 여기서 받는다)
```

**바깥에서 안으로 하나씩 고르는 구조**다. 서브넷을 못 고르면 인스턴스를 만들 수 없다 —
"이 서버를 어느 건물, 어느 방에 놓을지"가 정해지지 않은 상태이기 때문이다.

---

## 1. 리전과 가용 영역(AZ)

**리전** = 지리적 위치. 서울(`ap-northeast-2`), 버지니아(`us-east-1`) 등.

- **거의 모든 자원이 리전에 묶인다** — 인스턴스·EBS·S3 버킷·Elastic IP.
  리전을 잘못 고르면 나중에 옮기는 게 아니라 **다시 만들어야 한다.**
- 한국 사용자 기준 왕복 지연: 서울 **10ms대**, 버지니아 **200ms대**.

**가용 영역(AZ)** = 한 리전 안의 물리적으로 분리된 데이터센터. 서울은 `2a`·`2b`·`2c`·`2d` 4개다.

> **AZ가 나뉜 이유는 한쪽이 죽어도 다른 쪽은 살아 있게 하려는 것**이다.
> 서버를 두 대 이상 둘 때 서로 다른 AZ에 놓는 게 기본이다.
> 우리는 지금 한 대라 어느 AZ든 상관없다.

---

## 2. VPC — 내 전용 사설 네트워크

**VPC(Virtual Private Cloud)** = AWS 안에 만든, 나만 쓰는 네트워크 공간.

우리 것은 `172.31.0.0/16`이다. 계정을 만들면 리전마다 **기본 VPC**가 하나씩 생겨 있다.

### CIDR 표기 읽는 법

`172.31.0.0/16`의 `/16`은 **앞에서 16비트가 고정**이라는 뜻이다.

| 표기 | 고정되는 부분 | 쓸 수 있는 주소 |
|---|---|---|
| `172.31.0.0/16` | `172.31.` | 약 **65,536**개 (`172.31.0.0` ~ `172.31.255.255`) |
| `172.31.16.0/20` | `172.31.16~31.` | 약 **4,096**개 |
| `172.31.22.197/32` | 전부 | **1**개 (그 주소 딱 하나) |

**숫자가 클수록 좁다.** `/32`는 주소 하나를 가리키므로, 보안 그룹에서 "내 IP만" 을
고르면 `1.2.3.4/32` 같은 형태로 들어간다.

> `172.16.x.x`·`10.x.x.x`·`192.168.x.x`는 **사설 대역**이다. 인터넷에서 직접 못 찾아온다.
> 집 공유기가 주는 `192.168.0.x`와 같은 성격이다.

---

## 3. 서브넷 — VPC를 쪼갠 한 덩어리

**서브넷 = VPC의 주소 범위를 잘라낸 조각이고, 반드시 AZ 하나에 속한다.**

기본 VPC에는 보통 AZ마다 서브넷이 하나씩, `/20` 크기로 만들어져 있다:

| 서브넷 | AZ |
|---|---|
| `172.31.0.0/20` | ap-northeast-2**a** |
| `172.31.16.0/20` | ap-northeast-2**b** |
| `172.31.32.0/20` | ap-northeast-2**c** |
| `172.31.48.0/20` | ap-northeast-2**d** |

### 왜 서브넷을 골라야 하나 — 이유 셋

**① AZ가 결정된다.** 인스턴스는 물리적으로 어딘가에 있어야 한다.
서브넷을 고르는 행위가 곧 **"어느 데이터센터에 놓을지"** 를 고르는 것이다.

**② 사설 IP가 여기서 나온다.** `172.31.16.0/20` 서브넷에 인스턴스를 만들면
`172.31.22.197` 같은 주소를 받는다 — 앞서 본 **비공개 IP가 바로 이것**이다.

**③ 인터넷에 나갈 수 있는지가 여기서 갈린다.** 다음 절.

## 4. 퍼블릭 서브넷 vs 프라이빗 서브넷

**서브넷 자체에 "퍼블릭"이라는 설정값은 없다.** 붙어 있는 **라우팅 테이블**이 결정한다.

```
퍼블릭 서브넷   : 0.0.0.0/0 → 인터넷 게이트웨이(IGW)   ← 인터넷과 오간다
프라이빗 서브넷 : 0.0.0.0/0 경로가 IGW로 가지 않음      ← VPC 안에서만
```

`0.0.0.0/0`은 "그 밖의 모든 곳"이라는 뜻이다. 그 트래픽을 IGW로 보내면 인터넷과 통한다.

**웹 서버가 인터넷에서 보이려면 두 가지가 다 필요하다:**

1. **퍼블릭 서브넷**에 있을 것 (라우팅이 IGW로)
2. **공인 IP를 가질 것** — 인스턴스 생성 시 `퍼블릭 IP 자동 할당 = 활성화`,
   또는 Elastic IP 연결

> **우리는 Elastic IP를 붙인다.** 자동 할당 IP는 인스턴스를 중지·시작하면 **바뀌어서**
> 도메인(A 레코드)과 보안 그룹 설정이 전부 어긋난다.

### 우리 구성에서는

지금은 **한 대에 앱·DB·Redis가 다 있으므로 퍼블릭 서브넷 하나면 충분하다.**
DB를 별도 인스턴스나 RDS로 분리하면 그때 DB를 프라이빗 서브넷에 넣는다 —
**DB가 인터넷에서 아예 보이지 않게** 하는 것이 원래 모양이다.

## 5. 방화벽은 세 겹이다 (헷갈리기 쉬운 부분)

| 무엇 | 어디에 붙나 | 성격 | 우리 설정 |
|---|---|---|---|
| **보안 그룹** | 인스턴스 | **상태 저장** — 나간 요청의 응답은 자동 허용. **허용 규칙만** 있다 | 22·47821은 내 IP, 80·443은 전체 |
| **네트워크 ACL** | 서브넷 | 상태 비저장 — 들어오고 나가는 걸 각각 써야 한다 | 기본값(전부 허용) 그대로 |
| **ufw** | 리눅스 OS 안 | 호스트 방화벽 | 22·80·443·47821 |

**보안 그룹과 ufw를 둘 다 통과해야 한다.** 하나만 막혀도 증상은 똑같이 "시간 초과"라
원인을 착각하기 쉽다. NACL은 기본값이 전부 허용이라 평소엔 신경 쓰지 않는다.

---

## 6. "서브넷을 찾을 수 없습니다" 해결

기본 VPC는 있는데 **그 안에 서브넷이 없는 상태**다. 기본 서브넷이 지워졌을 때 생긴다.

### 방법 A — 기본 서브넷을 되살린다 (권장)

1. **VPC** 콘솔 → 좌측 **서브넷** → **서브넷 생성**
2. **VPC**: `vpc-0016d380c93115f70` (172.31.0.0/16) 선택
3. 서브넷 설정:
   - 이름: `playground-public-2a`
   - 가용 영역: **ap-northeast-2a**
   - IPv4 CIDR: **`172.31.0.0/20`**
4. **생성**

만든 서브넷을 퍼블릭으로 만든다:

5. 서브넷 선택 → **작업** → **서브넷 설정 편집** → **퍼블릭 IPv4 주소 자동 할당** 체크
6. **라우팅 테이블** 탭 확인 — `0.0.0.0/0 → igw-…`가 있어야 한다.
   없으면 → 좌측 **인터넷 게이트웨이**에 IGW가 있는지 보고, 없으면 만들어 VPC에 연결한 뒤
   라우팅 테이블에 `0.0.0.0/0 → IGW` 경로를 추가한다.

### 방법 B — 기본 VPC를 통째로 다시 만든다

기본 VPC까지 손상됐다면 이쪽이 빠르다. **IGW·라우팅·AZ별 서브넷이 한 번에 만들어진다.**

- **VPC** 콘솔 → **작업** → **기본 VPC 생성**
- 기존 기본 VPC가 남아 있으면 먼저 지워야 한다 — **그 안에 쓰는 자원이 없을 때만**.

> 지금은 아무것도 안 올라가 있으니 B가 안전하고 빠르다.
> 나중에 자원이 올라간 뒤에는 절대 이렇게 하지 않는다.

### 그다음

인스턴스 생성 화면으로 돌아가 **서브넷** = 방금 만든 것, **퍼블릭 IP 자동 할당** = **활성화**.
(Elastic IP를 붙일 거라 자동 할당 IP는 어차피 대체되지만, 활성화해 두면
Elastic IP를 연결하기 전에도 접속해 볼 수 있다.)

## 용어 한 줄 정리

| 용어 | 한 줄 |
|---|---|
| 리전 | 지리적 위치. 자원이 여기 묶인다 (서울 = ap-northeast-2) |
| 가용 영역(AZ) | 리전 안의 분리된 데이터센터. 서울은 4개 |
| VPC | 내 전용 사설 네트워크 (172.31.0.0/16) |
| 서브넷 | VPC를 쪼갠 조각. **AZ 하나에 속한다** |
| CIDR | 주소 범위 표기. `/` 뒤 숫자가 클수록 좁다 |
| 인터넷 게이트웨이(IGW) | VPC를 인터넷과 잇는 문 |
| 라우팅 테이블 | 어디로 보낼지의 규칙. **퍼블릭/프라이빗을 가르는 것** |
| 보안 그룹 | 인스턴스 방화벽. 허용 규칙만, 상태 저장 |
| 네트워크 ACL | 서브넷 방화벽. 기본은 전부 허용 |
| Elastic IP | 고정 공인 IP. 붙여야 재시작해도 안 바뀐다 |
| 사설 IP | 서브넷에서 받는 내부 주소(172.31.x.x). 인터넷에서 접근 불가 |
