목적: 스텁을 실물로 바꾼다. **전부 포트 뒤에 있어 어댑터 교체 중심**이다.

|---|---|---|---|---|

| H2 | 이미지 | `LocalImageStorageService` (63줄) | S3 어댑터 + 공개 URL 규칙 | D1 |
| H3 | export 큐 | 인메모리 `Channel`(무제한) | **재시작 시 유실** — DB 상태 기반 복구 or 지속 큐 | — |
| H4 | JWT 무효화 | ✅ **구현됨** (2026-08-02) | 스테이징에서 실제 Redis로 확인만 남음 | H0 |

**완료 기준** — 스테이징에서 이메일 실제 수신 · 이미지 S3 업로드/조회 · 재시작 후 export 복구 ·
로그아웃 후 기존 토큰 거부 · OG 카드 한글 정상 렌더.

### H0·H4 완료 (2026-08-02) — 실제 Redis로 검증됨

로컬 Redis(`Others/FetchRedis.ps1`)를 들여 **다섯 시나리오를 실물로 확인했다.**

| 확인 | 결과 |
|---|---|
| 로그아웃 → 같은 토큰으로 `/api/auth/me` | **401** ✅ |
| 다른 기기 토큰은 유지되는지 (jti 단위) | 200 유지 ✅ |
| 탈퇴 → 그 사용자의 **모든** 토큰 | 둘 다 401 ✅ |
| Redis 중단 시 로그인·조회 (fail-open) | 정상 + Warn 로그 ✅ |
| Redis 죽은 채 기동 → 나중에 살아나면 | **자동 재연결 후 무효화 동작** ✅ |

Redis 키 형태도 확인: `auth:revoked:token:{jti}` · `auth:revoked:user:{userId}`.

> **검증 중에 운영 버그를 하나 잡았다** — StackExchange.Redis 기본값(`AbortOnConnectFail=true`)이면
> 기동 시점에 Redis가 죽어 있을 때 연결이 등록되지 않아 **Redis가 살아나도 앱 재시작 전까지
> 영영 붙지 않는다.** 배포 중 블립 한 번이면 무효화가 조용히 죽는다는 뜻이라 `false`로 바꿨다.

**스테이징에 남은 것**: ElastiCache 엔드포인트를 `RedisConfig__Connections__0__ConnectionString`으로
주입하고 위 5개를 한 번 더 확인. 역할 승격 직후 새 토큰이 정상 동작하는지도 함께 본다.

## R5. 운영 준비

백업·도메인·HTTPS·OAuth 등록은 배포 절차에 포함돼 있다(`Deploy/README.md`).
**여기 남는 것은 배포 이후에 별도로 갖춰야 할 것들뿐이다:**

- **모니터링·알림** — 최소한 "서버가 죽었다"를 아는 수단.
  지금은 아무도 모른다. 헬스체크 + 이메일/슬랙 알림이 최소 구성.
- **로그 수집** — 현재 파일·journald에만 쌓인다. 인스턴스를 잃으면 로그도 잃는다.
- **복구 연습** — 백업에서 실제로 되살려 본다. 절차는 `Deploy/Runbook.md` "최악",
  **해 보지 않은 복구 절차는 없는 것과 같다.**
- **Redis fail-open 경고 모니터링** — 무효화가 조용히 죽는 상태를 알아야 한다
  (`Revocation check skipped` 로그).

## 순서와 병행

```
R1 기능 마감 ─┐
              ├─→ R3 하드닝(H3·H4 먼저) ─→ R4 배포 ─→ R5 운영
R2 테스트 ────┘        ↑
                   D1~D4 결정 필요(H1·H2·H5·H6)
```

- **R1·R2는 지금 바로, 결정 없이 시작 가능** — 여기부터 하는 게 맞다
- **R3의 H3(export 내구성)·H4(JWT 무효화)도 결정 무관** — R2와 병행
- D1~D4가 정해지는 대로 H1·H2·H5·H6 → R4

## 권장 착수 순서

1. **R2-1 DB 프로시저 계약 테스트** — 안전망의 가장 큰 구멍이고, 이후 모든 수정의 바닥이 된다
2. **R1-2 전 화면 수동 검수** — 결함 목록이 나와야 R1-1의 "필요/보류" 판단이 근거를 얻는다
3. R1-1 결함·P1 처리
4. R2-2 API 통합 테스트
5. R3 H3·H4
6. (D1~D4 확정 후) R3 나머지 → R4 → R5
