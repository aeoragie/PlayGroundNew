# 전체 기능 테스트 시나리오 (2026-07-21 수립)

> 지금까지 개발한 전 기능을 롤별로 훑는 통합 기능 테스트. 순서: **롤 정의 → 테스트 계정·데이터 →
> Phase 1(가입·대시보드) → Phase 2(팀·선수·경기 생성) → Phase 3(기능별)**.
> 검증 계정은 `ft-*`(functional test) 네임스페이스 — 기존 `verify-*`(단위 검증)와 분리. **로컬 전용.**
> 비밀번호는 전부 `password123!`. 이메일 로그인은 find-or-create라 **첫 로그인이 곧 가입**이다.

## 1. 롤 정의 (테스트 주체)

| # | 롤 | 앱 내 정체 | 무엇을 테스트하나 |
|---|---|---|---|
| R1 | **팀 관리자** (TeamAdmin) | 팀 온보딩으로 팀 생성·소유 | 팀 대시보드 6섹션·로스터 쓰기·경기 입력·공개홈 관리·Claim 승인·수정신청 |
| R2 | **보호자** (Parent/Guardian) | 자녀 선수 프로필을 대리 관리(FamilyLink·IsGuardianManaged=1) | 자녀 N명·허브·Claim(코드/프로필)·자녀 대시보드·보호자 수정신청·공개범위 |
| R3 | **선수 본인** (Player, self) | 성인 선수가 본인 프로필 관리(IsGuardianManaged=0) | 본인 프로필·커리어·포트폴리오·공개 프로필·"본인 계정 사진 편집 제외" 규칙 |
| R4 | **General** (역할 미설정) | 로그인만 하고 역할 스킵 | 역할 선택 화면·General 진입·Records 공개 열람 |
| R5 | **에이전트** (Agent) — *제한적* | feature flag `AgentApproval` 뒤. 요청 생성은 외부 에이전트 서비스 몫 | 열람 요청 심사 화면·권한 뷰·30일 만료 (flag on + 시드로만) |
| — | **주최측(대회 운영)** — *로그인 롤 아님* | PlayGround 밖 서비스. 공식 경기·순위표·수정신청 심사의 주체(설계 결정 7) | **DB 시드로 흉내** — 공식 대회·경기·순위표·수정신청 Accepted/Rejected |

> **추가로 필요한 롤 결론**: 위 R1~R5 + "주최측(시드)"이면 전 기능을 덮는다. 코치는 별도 로그인
> 대시보드가 없어(팀 정보의 코칭스태프 데이터일 뿐) 테스트 주체가 아니다. 관리자(admin)도 화면 없음.

## 3. 테스트 데이터 (Phase 2에서 생성)

**팀**
- 팀A **테스트유나이티드** (ft-team-a) — 로스터 5명: 강민(FW·9), 정우(MF·8), 도현(DF·4), 시온(GK·1), 하람(MF·7)
- 팀B **라이벌FC** (ft-team-b) — 로스터 3명

**보호자 자녀 (ft-parent)**
- 자녀1 **박서준** — 선수 온보딩으로 직접 생성(대리 관리)
- 자녀2 = 팀A 로스터의 **강민** — 코드 또는 공개 프로필 경유로 Claim → 팀A 관리자 승인 (자녀2가 팀A 소속이 되어 시즌통계·순위표 교차 테스트)

**경기**
- 친선: 팀A vs 팀B — **팀A 관리자가 UI로 입력**(B1). 시즌통계 "친선 별도" 표기 확인용
- 공식: 대회 **테스트리그 2026** + 팀A vs 팀B 공식 경기 + 순위표 + 강민 출전·득점 — **DB 시드(주최측 흉내)**. 순위표·Records·자녀 공식 시즌통계·수정신청·권한 뷰 테스트용

## 7. 실행 방식

- **Phase 1·2(가입·데이터 생성)**: 헤드리스 자동화 또는 UI 수동. 자동화 시 로그인=API, 온보딩=UI 클릭,
  공식경기=SQL 시드. 자동화 스크립트는 `Source/Tools/Verification/ft-*.js`로 둔다.
- **Phase 3(기능별)**: 화면 확인이 본체라 **UI 수동 체크리스트**가 기본. 핵심 왕복(Claim 승인·수정신청·
  취소 등)은 자동화 스크린샷으로 보강.
- 테스트 종료 후 `ft-*` 계정·데이터는 정리 스크립트로 원복(또는 로컬 리셋).

> 이 문서는 체크리스트다. 각 ID를 돌리며 PASS/FAIL을 표시하고, FAIL은 재현 스텝과 함께 기록한다.
