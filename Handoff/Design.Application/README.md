# Handoff: 지원 (Application)

> 대상 저장소: `C:\Workspace\PlayGroundNew` · 압축 해제 위치: `Handoff\Design.Application` (신규)
> DesignWorkOrders ② — 획득 루프 완성. 선행 결정: `DECISION.TEAMEXPLORE.md`(선수 조건 검색 화면 없음 → 수급은 "선수가 찾아와 지원 + 에이전트 추천" 역방향 파이프라인으로 성립).

## 흐름
팀이 모집 공고 게시 → 선수·보호자가 **공개홈 모집 탭**에서 지원 → 팀 관리자가 **선수 모집 섹션의 지원자 리스트**에서 상태 전환(대기→검토중→수락/보류) → 수락 시 **선수단 초대**(보호자 수락으로 로스터 편입).
**경계**: PlayGround는 지원 접수·상태 관리까지. 입단 계약·회비 정산은 서비스 밖(팀 오프라인).

## 1. 공고 카드 (공개홈 모집 탭) — 기존 SPEC.TEAMPUBLICHOME ④ 계승
- 구조: 제목 + **모집중 뱃지(teal `#1b8579`/`rgba(46,196,182,.12)`)** + 기간·정원 메타 + 조건 칩 + **"지원하기" 네이비 버튼**
- **공개홈의 오렌지 CTA는 히어로·모바일 고정 바의 "입단 문의" 1개뿐** — 지원 버튼은 네이비(PatternsIndex 전역규칙 1 준수)
- 마감 공고 = 회색 뱃지 + opacity .75 + 버튼 비활성 · 이미 지원한 공고 = "지원 완료 · 상태 보기"(네이비 아웃라인)
- 기존 "모집 공고가 없어도 문의할 수 있어요" 카드 유지

## 2. 지원 폼 — PC 모달 / 모바일 바텀시트
- **지원 선수**: 연결된 자녀 중 선택(모바일=바텀시트 목록). 프로필 정보(생년·포지션·기록)가 함께 전달됨 — 별도 입력 없음
- **희망 포지션**: 공고에 명시된 포지션만 라디오 카드
- **자기소개**: 500자 카운터
- **연락처**: 계정 값 **읽기 전용** + **수락 후에만 팀에 전달**(서버 마스킹 원칙 유지)
- 게스트가 "지원하기" → `/auth?returnUrl`로 로그인 후 **폼 자동 재개**(Navigation 규칙)
- 연결된 자녀 없으면 폼 대신 안내 "먼저 자녀를 연결해 주세요" + Claim CTA
- **중복 지원 차단**: 같은 선수 + 같은 공고. 보류 후 재지원은 30일 경과 시 허용

## 3. 팀 측 — 선수 모집 섹션의 지원자 리스트 **확장**(신규 섹션 아님)
- 기존 SPEC.TEAMDASHBOARD §6 자리 그대로(공고 카드 2장 아래). 상태 뱃지 어휘·톤 계승: **대기 회색 / 검토중 오렌지톤 / 테스트 확정 teal**, 신설은 수락(teal)·종료(회색)만
- 상태 세그먼트(대기 N / 검토중 N / 종료) — 카운트 표시
- 지원 경로 구분: 직접 지원(teal 아바타) / **에이전트 추천(violet + "추천" 뱃지 + 추천자 이름)**
- 액션: 기존 **[프로필 / 테스트 요청(네이비)]** 버튼 유지 + ⋯에 수락·보류(파괴 맨 아래 레드 → 확인 모달, 사유 입력 선택). 모바일 ⋯ = 바텀시트
- 행은 액션형(행 탭 없음 — TableList 규칙)

## 4. 수락 → 로스터 편입
① 지원 상태 = 수락 ② 보호자에게 **선수단 초대** 알림 ③ 보호자 수락 시 `SoccerTeamPlayers` 생성 ④ 이때 연락처 마스킹 해제
**팀이 일방적으로 로스터에 넣지 않음** — 보호자 동의가 편입 조건(Claim 원칙과 동일)

## 5. 지원자 측 — 내 지원 현황 (허브 자녀 카드 · 선수 대시보드)
- 상태 문구는 지원자 관점으로 완화: 대기="팀에 전달됐어요" / 검토중="팀이 확인했어요" / 보류="이번에는 함께하지 못했어요"
- **보류 뱃지는 중립 회색 "종료"** — 레드 금지(아이가 보는 화면)
- 상태 변경 시 알림 발송 · 대기 상태에서 지원 취소 가능

## 스키마
- `SoccerRecruitPosts`: TeamId · 제목 · 연령 · 포지션(복수) · 정원 · 모집기간 · 본문 · 상태(Open/Closed)
- `SoccerApplications`: PostId · PlayerId · GuardianId · 희망포지션 · 자기소개 · 상태(Pending/Reviewing/Accepted/Rejected — 화면 어휘 대기/검토중/수락/종료) · 경로(Direct/AgentRef) · RefAgentId · CreatedAt
- **기존 `TeamRecommendation`(에이전트 추천 수신)이 있으면 AgentRef 경로로 통합** — 중복 파이프라인 금지
- 알림: 새 지원 → 팀 관리자 / 상태 변경 → 보호자 / 수락 → 선수단 초대

- `Application Mobile.dc.html` — 모바일(390px: 공고 카드/바텀시트 폼/버튼 행 리스트/내 지원 현황)

```
   게스트는 /auth?returnUrl 후 폼 자동 재개.
3) 지원 폼(PC 모달/모바일 바텀시트): 자녀 선택·희망 포지션·자기소개·연락처 읽기 전용,
   중복 지원 차단(30일 재지원).
4) 팀 대시보드 선수 모집 섹션의 지원자 리스트 확장(새 섹션 만들지 마): 상태 세그먼트,
   기존 [프로필/테스트 요청] 유지 + ⋯ 수락·보류, 에이전트 추천 violet 뱃지.
5) 수락 → 보호자 선수단 초대 알림 → 보호자 수락 시 로스터 편입 + 연락처 마스킹 해제.
6) 내 지원 현황(허브 자녀 카드·선수 대시보드) + 상태 변경 알림.
완료 후 게스트 지원→로그인 재개→팀 수락→보호자 수락→로스터 편입 왕복으로 검수 요청해.
```
