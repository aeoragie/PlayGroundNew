# DECISION.RECORDS — 상태 필터 + 순위표 "내 팀 행" 마킹

> 위치: `Handoff\DECISION.RECORDS.md` · DesignWorkOrders ⑧ · 기준: `Design.Records`(설계 결정 5개 확정본)
> 확정되면 `SPEC.RECORDS.md`에 해당 절을 보강한다. **[결정 필요]** 표시 항목만 답하면 됨.

## 1. 상태 필터 칩 — 추가할까?

**현행 확정 결정(설계 결정 2)**: "상태 필터 제거, 색으로 표시" — 행 좌측 컬러 바(진행중 teal / 예정 네이비 / 종료 회색+opacity .55) + 범례, 정렬은 진행중→예정→종료 자동.

| 대안 | 내용 | 평가 |
|---|---|---|
| **A. 현행 유지 (추천)** | 전부 표시 + 색 + 자동 정렬 | 선택을 강요하지 않음 · 종료 대회도 스크롤로 만남(전환 기회) · 필터 상태 기억/URL 동기화 부담 없음 |
| B. 상태 칩 추가 | 전체/진행중/예정/종료 칩 | 정보량 감소 효과는 있으나, **이미 세로 축이 4겹**(세그먼트 → 연령 아코디언 → 정렬 → 색)이라 다섯 번째 축이 됨. SearchFilter "칩=좁히기" 규칙상 가능하지만 이 화면의 문제는 "필터 부족"이 아니라 "축 과다" |
| C. 종료만 접기 | "종료된 대회 N개 보기" 아코디언 | 상태 칩 없이 목록 길이 문제만 해결 — B의 절반 비용 |

**추천: A 유지 + 다음 조건에서만 C로 승격** — 한 연령 아코디언 안 종료 대회가 **5개를 넘고** 그 비중이 절반 이상일 때, 그 아코디언 하단에만 "종료된 대회 N개 보기"를 붙인다(TabAccordion 규칙 재사용, 전역 필터 아님).

근거: 올해만 노출 + 아카이브 분리(결정 1)로 이미 목록이 짧다. 상태 칩은 아카이브와 역할이 겹치고("종료만 보기" = 사실상 아카이브), 연령 아코디언·대회/리그 세그먼트와 함께 쓰면 사용자가 자기가 무엇을 걸러 놓았는지 잃는다.

**[결정 필요 ①]** A 유지(조건부 C) vs B 칩 추가. → 추천 A.

## 2. 순위표 "내 팀 행" 마킹 — 주체는?

Records 상세는 `AllowAnonymous` 공개 화면이므로 "내 팀"이 없을 수 있다.

**확정 제안 — 주체 우선순위**
1. **팀 관리자(TeamStaff)** → 담당 팀 전부 마킹(복수 팀 가능)
2. **보호자(FamilyLink)** → 연결된 자녀의 소속팀 마킹(자녀 2명이 다른 팀이면 둘 다)
3. **선수 본인 계정** → 소속팀
4. **에이전트** → 마킹 없음 (관심 선수 소속팀 마킹은 열람 승인 범위 밖 정보 노출로 읽힐 수 있음)
5. **게스트** → 마킹 없음 · 대신 순위표 하단에 1줄 안내 "로그인하면 우리 팀 순위를 눈에 띄게 볼 수 있어요"(텍스트 링크, 배너 아님)

표시는 `TableList` 규칙 그대로: 네이비 보더 + `rgba(35,64,142,.04)` 배경 + "내 팀" 뱃지(행당 뱃지 1개 — 진출권 teal 틴트와 겹치면 **내 팀 마킹이 우선**, 진출권은 순위 숫자 색으로만 표현).

**상단 고정 요약(스크롤 밖일 때)** 노출 조건 — 4개 전부 충족:
- 내 팀이 이 순위표에 존재하고
- 그 행이 **뷰포트 밖**이며
- 순위표 행이 **8개 이상**이고
- 스크롤이 순위표 영역 안에 있을 때
형태: 순위·엠블럼·팀명·승점 1줄(높이 PC 44px / 모바일 48px), 탭하면 해당 행으로 스크롤(scrollIntoView 금지 — 컨테이너 scrollTop 계산). 복수 팀이면 **가장 높은 순위 1팀만**.

**[결정 필요 ②]** 위 우선순위 5단계 + 고정 요약 조건 승인 여부. 특히 보호자 자녀 소속팀 마킹 포함 여부(포함이 추천 — 학부모가 Records를 가장 많이 본다).
